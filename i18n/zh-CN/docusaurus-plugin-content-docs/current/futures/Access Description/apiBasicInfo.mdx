#### 基础地址

- **USDT-M:** `https://fapi.xt.com` （适用于 U 本位合约）
- **Coin-M:** `https://dapi.xt.com` （适用于币本位合约）

---

#### 网络建议

由于高延迟和稳定性差的原因，**不建议通过代理访问 XT API**。

---

#### 请求方式

- **GET 请求：** 参数放在 **QueryString** 中。
- **POST 请求：** 参数可以放在 **RequestBody** 或 **QueryString** 中。

##### 当参数放在 QueryString 中时：
必须在 HTTP Header 中添加：
```bash
Content-Type: application/x-www-form-urlencoded
```

##### 当参数放在 RequestBody 中时：
必须在 HTTP Header 中添加：
```bash
Content-Type: application/json
```

---

#### 接口分类

XT API 接口分为 **公共接口** 和 **用户接口**。

##### 🟢 公共接口
- 无需身份认证。
- 参数直接放入 QueryString 中。
- 通常使用 **GET** 方法。

**示例：**
```bash
curl -G "https://fapi.xt.com/future/market/v1/public/symbol/detail?symbol=btc_usdt"
```

**或：**
```bash
curl -G "https://fapi.xt.com/future/market/v1/public/symbol/detail" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "symbol=btc_usdt"
```

##### 🔒 用户接口
- 需要在 Header 中传入认证参数。
- 除了 QueryString 或 RequestBody 参数外，至少需要以下四个 Header：

| Header | 说明 |
|--------|------|
| `validate-appkey` | 用户公钥 |
| `validate-timestamp` | 当前时间戳（毫秒） |
| `validate-signature` | 请求签名 |
| `Content-Type` | 请求类型（`application/json` 或 `application/x-www-form-urlencoded`） |

**GET 示例：**
```bash
curl -G "https://fapi.xt.com/future/user/v1/compat/balance/list" \
  -H "validate-appkey: $APPKEY" \
  -H "validate-timestamp: $TIMESTAMP" \
  -H "validate-signature: $SIGNATURE" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "queryAccountId=1234567890"
```

**POST 示例：**
```bash
curl -X POST "https://fapi.xt.com/future/user/v1/user/collection/add" \
  -H "validate-appkey: $APPKEY" \
  -H "validate-timestamp: $TIMESTAMP" \
  -H "validate-signature: $SIGNATURE" \
  -H "Content-Type: application/json" \
  -d '{"symbol":"btc_usdt"}'
```

> 不需要签名的接口将在文档中额外说明。

#### 限流规则

U 本位合约（`fapi.xt.com`）和币本位合约（`dapi.xt.com`）适用相同的频率限制。

- 私有接口（需要签名）按 **API Key** 限频。
- 公开接口（无需签名）按 **客户端 IP** 限频。
- 部分接口共用一份额度。以"组"列出的接口，限额针对该组所有接口的请求总数。
- 每项限制包括**持续速率**和**突发容量**：可以一次性发出不超过突发容量的请求，之后额度按持续速率恢复。

##### 超出限制时

- 请求返回 HTTP 状态码 `429 Too Many Requests`。
- 受限接口的每个响应都带有以下响应头：
  - `X-RateLimit-Remaining`：当前还能立即发出的请求数
  - `X-RateLimit-Replenish-Rate`：每秒持续速率
  - `X-RateLimit-Burst-Capacity`：突发容量
  - `X-RateLimit-Requested-Tokens`：单次请求消耗的额度
- 收到 429 后请先等待再重试（例如先等 1 秒，连续 429 时每次等待时间翻倍），不要立即循环重试。
- 需要批量查询多个交易对时，优先使用一次返回全部交易对的接口，或改用 WebSocket 订阅代替轮询。
